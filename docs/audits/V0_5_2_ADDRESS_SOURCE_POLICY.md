## Purpose

This policy defines the approved source-of-truth rules for addresses used by NST Lattice applications, protocol clients, config, governance gates, transaction rail packages, public sites, corporate sites, First Nations interfaces, admin consoles, and deployment readiness artifacts.

No application, package, demo, public interface, corporate interface, First Nations interface, admin console, protocol client, governance gate, config map, or transaction rail may rely on an address unless the address source is approved under this policy.

The purpose is to prevent the project from using stale, pasted, screenshot-derived, chat-derived, memory-derived, guessed, mock, Anvil, Base Sepolia, placeholder, or unapproved addresses as production values.

## Approved address source hierarchy

The approved address source hierarchy is:

1. Final production address approval receipt signed or explicitly approved by the required authority.
2. Final production address source-of-truth response reviewed under the response review checklist.
3. Final production address collection package populated from approved source-of-truth responses.
4. Deployment receipt generated by a controlled deployment process.
5. Explorer-verified deployed contract address matching the deployment receipt.
6. Base Sepolia deployment inventory for testnet-only demo addresses.
7. Local Anvil output for local development only.

No lower-quality source may override a higher-quality source.

No address may be accepted from memory, screenshots, chat text, guesses, copied UI fragments, unverified pasted text, untracked local files, or undocumented external files.

## Production address rule

A production address is acceptable only when all of the following are true:

- It is public.
- It is checksum reviewed.
- It is source-of-truth documented.
- It has approval evidence.
- It has an owner category.
- It has a network scope.
- It has a chain ID scope.
- It has a custody type.
- It has an intended config field or role.
- It has no-secret confirmation.
- It has no-placeholder confirmation.
- It has no-local confirmation.
- It has no-Anvil confirmation.
- It has no-Base-Sepolia-as-production confirmation.
- It is not derived from screenshots.
- It is not derived from chat text.
- It is not derived from memory.
- It is not derived from guesswork.
